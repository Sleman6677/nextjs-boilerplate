# Serag Lashes · سراج لاشز

موقع استوديو رموش ومتجر إلكتروني، مبني بـ Next.js 16 (App Router) وTailwind CSS v4، بثلاث لغات: العربية والعبرية (من اليمين لليسار) والإنجليزية.

## الصفحات

كل صفحة موجودة بثلاث لغات: `/ar/...` و`/he/...` و`/en/...`. من يفتح `/` يُحوَّل للغة متصفحه أو لآخر لغة اختارها.

| المسار | الصفحة |
|---|---|
| `/` | الرئيسية |
| `/services` | الخدمات والأسعار |
| `/gallery` | المعرض |
| `/shop` | المتجر: المنتجات مقسّمة لمجموعات مع أزرار تصفية |
| `/cart` | سلة المشتريات |
| `/checkout` | إتمام الطلب: العنوان، كوبون أو خصم الطلب الأول، النقاط، طريقة الدفع |
| `/login` | تسجيل الدخول برمز يصل إلى البريد الإلكتروني (بدون كلمة سر) |
| `/account` | حساب الزبون: الطلبات الحالية والسابقة وحالتها، العناوين، البيانات، النقاط |
| `/about`, `/booking` | قصة العلامة، وحجز موعد عبر واتساب |
| `/admin` | لوحة التحكم لصاحب المتجر (بالعربية) |

## كيف يعمل المتجر

- **رقم لكل طلب**: الطلبات تُرقَّم تلقائيًا ابتداءً من 1001.
- **طرق الدفع**: بطاقة ائتمان وApple Pay وBit عبر صفحة دفع PayPlus، ونقدًا عند الاستلام. إذا لم يكن Bit مفعّلًا في PayPlus، يظهر للزبون تحويل يدوي إلى رقم Bit.
- **خصم واحد فقط في كل طلب**: إمّا كوبون وإمّا خصم الطلب الأول. الكوبون يحلّ محل خصم الطلب الأول.
- **النقاط**: كل طلب يكسب نسبة من قيمة المنتجات المدفوعة (افتراضيًا 5٪، والنقطة = 1 ₪). تُضاف النقاط عند تأكيد التوصيل، وتُستعمل في طلب قادم، ولا تدفع ثمن التوصيل. إلغاء الطلب يعيد النقاط المستعملة.
- **التوصيل المجاني**: فوق مبلغ يُحدَّد في اللوحة، ويُحسب بعد الخصم.
- الأسعار تُحسب دائمًا على الخادم من قاعدة البيانات، لا من المتصفح.

## لوحة التحكم `/admin`

- **نظرة عامة**: الطلبات التي تحتاج تجهيزًا، مبيعات اليوم والشهر، آخر الطلبات.
- **الطلبات**: بحث برقم الطلب أو الاسم أو الهاتف أو المدينة، وتصفية حسب الحالة. في صفحة الطلب: نقل الحالة خطوة بخطوة (جديد ← قيد التجهيز ← تم الشحن ← تم التوصيل)، تأكيد استلام الدفع، إلغاء الطلب، ملاحظات داخلية، وزر واتساب يفتح رسالة للزبون بلغته.
- **المنتجات**: إضافة وتعديل وإخفاء وحذف، بالاسم والوصف بثلاث لغات (العربية تكفي)، السعر، المجموعة، وصورة أو رسم علبة.
- **المجموعات**: أسماء المجموعات وترتيبها وإظهارها.
- **الكوبونات**: نسبة أو مبلغ ثابت، حد أدنى للطلب، تاريخ بداية ونهاية، عدد مرات الاستعمال، مرة واحدة لكل حساب.
- **الزبائن**: عدد الطلبات ومجموع المشتريات ورصيد النقاط، مع إمكانية إضافة نقاط أو خصمها.
- **التوصيل والنقاط**: سعر التوصيل، حد التوصيل المجاني، نسبة خصم الطلب الأول، نسبة النقاط وقيمة النقطة.

## خطوات التفعيل (مرة واحدة)

بدون هذه الخطوات يعمل الموقع بستّ علب ثابتة، والطلب يُرسل عبر واتساب.

### 1. قاعدة البيانات (Supabase)

1. في Vercel: المشروع ← **Storage** ← **Create Database** ← **Supabase**، واربطها بالمشروع. هذا يضيف المتغيرات `POSTGRES_URL` و`NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY` تلقائيًا.
2. افتح لوحة Supabase ← **SQL Editor**، والصق محتوى الملف `supabase/migrations/20261105000000_shop.sql` كاملًا واضغط **Run**. هذا ينشئ الجداول، والمجموعات الثلاث، والعلب الست، والإعدادات الافتراضية. تشغيله مرة ثانية آمن.
3. في Supabase ← **Authentication** ← **Emails** ← **Templates**: في قالبَي **Magic Link** و**Confirm signup** ضع رمز الدخول في الرسالة، مثلًا:

   ```html
   <h2>رمز الدخول إلى Serag Lashes</h2>
   <p style="font-size:28px;letter-spacing:6px"><strong>{{ .Token }}</strong></p>
   ```

   بدون `{{ .Token }}` تصل رسالة برابط فقط بدل الرمز.
4. للإرسال الفعلي بكميات (أكثر من بضع رسائل في الساعة)، اربط خدمة بريد من **Authentication** ← **Emails** ← **SMTP Settings**.

### 2. حساب الإدارة

في Vercel ← **Settings** ← **Environment Variables** أضف:

- `ADMIN_EMAILS` = بريد صاحب المتجر (أكثر من بريد: افصل بينها بفاصلة).

ثم ادخل إلى `/admin` وسجّل الدخول بهذا البريد.

### 3. الدفع عبر PayPlus

من لوحة PayPlus: **API Key** و**Secret Key** و**UID صفحة الدفع**، ثم أضف في Vercel:

- `PAYPLUS_API_KEY`
- `PAYPLUS_SECRET_KEY`
- `PAYPLUS_PAYMENT_PAGE_UID`
- `PAYPLUS_ENV` = `staging` للتجربة بمفاتيح بيئة الاختبار (يُحذف عند التشغيل الحقيقي)
- `PAYPLUS_METHODS` (اختياري) = الطرق المفعّلة في صفحة PayPlus، افتراضيًا `card,bit,apple_pay`. مثال: إن لم يكن Bit مفعّلًا عند PayPlus ضع `card,apple_pay`.

بعد الدفع يرسل PayPlus إشعارًا موقَّعًا إلى `/api/payplus/callback`، فيصبح الطلب «مدفوع» وينتقل إلى «جديد» تلقائيًا. الإشعارات غير الموقَّعة بالمفتاح السري تُرفض.

بطاقة اختبار من توثيق PayPlus لبيئة staging: `5326-1402-8077-9844`، تاريخ `05/30`، CVV `000`.

### 4. أعد النشر

بعد إضافة المتغيرات: **Deployments** ← آخر نشر ← **Redeploy**.

> المفاتيح السرية مكانها إعدادات Vercel فقط، لا في الكود ولا في أي رسالة.

## صور المنتجات

من اللوحة: زر **رفع صورة** في صفحة المنتج (يعمل عند وجود `SUPABASE_SERVICE_ROLE_KEY`، والصور تُحفظ في Supabase Storage وتُصغَّر تلقائيًا قبل الرفع)، أو لصق رابط صورة. بدون صورة يظهر رسم علبة يُختار لونه وشكل الرموش فيه.

## بيانات ثابتة في الكود

في `lib/site.ts`: رقم واتساب، حساب إنستغرام وتيك توك، ساعات العمل، أسعار خدمات الاستوديو، عرض الزيارة الأولى، ورقم Bit للتحويل اليدوي. القيم المعلَّمة بـ `TODO` مؤقتة.

نصوص الموقع باللغات الثلاث في `lib/i18n/dictionaries/{ar,he,en}.ts`.

## التشغيل

```bash
npm install
npm run dev     # http://localhost:3000
npm run build
npm run lint
```

## ملاحظات تقنية

- `proxy.ts` يوجّه للغة المناسبة ويجدّد جلسة Supabase.
- قاعدة البيانات تُقرأ من الخادم فقط عبر `POSTGRES_URL`؛ كل الجداول مقفلة بـ RLS أمام الواجهة العامة لـ Supabase.
- صفحتا المتجر والسلة تُعرضان عند كل زيارة، فتظهر تعديلات اللوحة فورًا.
- كل الحركات تُعطَّل عند تفعيل «تقليل الحركة» في جهاز الزائر.
